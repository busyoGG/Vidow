# ADR 0001 —— 性能口径：帧时为主指标，资源占用为约束

- 状态：已采纳（2026-11-18）
- 相关：#性能优化

## 背景

优化请求是「cpu gpu 显存 内存 优化」。这四样各有各的降法，而且互相打架：
压 `%CPU` 往往靠少做事，稳帧往往靠多做准备（缓存、预烘、离屏）。没有事先说清
主指标，改动就没法比较，也没法拒绝。

用户的感知是**卡**，不是 `top` 里的数字。

## 决定

1. **主指标是帧时**：每场景取帧时中位 + 最大帧时（p99 之外单独记 max）。
2. **资源占用是约束**，不是目标：CPU、GPU busy、我们持有的显存、RSS 都不许因
   某条「优化」而变差；变好则是附赠。
3. **五套固定场景**，各采样 10 秒：`idle`（桌面空闲）、`drag`（单窗拖拽）、
   `game`（全屏 160Hz）、`multiscreen`（双屏 + 多窗 + 壁纸模糊）、
   `capture`（录屏/截屏，只用来比「别退化」）。
4. **采样协议**：每场景 3 轮 × 10 秒，取中位，并单独记最大值。三个数字（帧时、
   GPU busy、显存）缺一个，这次采样作废。
5. **采集通道**：
   - 帧时与各阶段耗时：vidow 自报的 `渲染统计`（进程内，不受别的进程干扰）；
   - GPU busy / 整卡显存：`/sys/class/drm/card*/device/gpu_busy_percent`、
     `mem_info_vram_used`（挑显存最大的那块卡）；
   - CPU：`perf stat`；RSS：`/proc/<pid>/smaps_rollup`。
6. **每条改动一个 commit，拿不到数字就撤**。

## 后果

- headless + `EGL_PLATFORM=surfaceless` 走真 radeonsi，但**没有扫描输出**，量到的
  是「画一帧多久」，不是上屏节奏。真机会话要量统计必须换构建重启（破坏性，
  须先取得同意）。
- **单位必须写清**：统计行每 500ms 打一次，`趟`、`重烘`、`链` 都是**累计在
  那个帧窗里**的，不是每帧值。要换算成「每帧」得用「总趟 ÷ 总帧」。
  （2026-11-18 曾把 `趟 279/样本` 误读成 `279/帧`，据此差点选错第一刀。）
- 不写 `test-perf.sh` 阈值门禁：llvmpipe 与真机差得远，真机数字受别的程序影响，
  门禁只会反复误报。等数字稳定再说。

## 备选方案

- **`%CPU` / `top` 视角作主指标**：否。它跟卡顿的相关性差，且会奖励「少做事」
  这种把问题推给下一帧的做法。
- **`radeontop` 采 GPU**：否，没装，sysfs 够用。
- **嵌套 wayland 后端采样**：否，实测嵌套实例里统计恒为 0。
