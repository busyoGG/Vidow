# ADR 0003 —— 「哪里慢」的四个分支与各自的下一步

- 状态：提议（等 Q1 的答案落地）
- 相关：ADR 0001（口径）、ADR 0002（实测：现状测不出成本）

## 为什么写这张表

ADR 0002 的实测把「优化什么」这个前提打掉了：桌面常态 CPU ≤2%、GPU ≤6%、
6 个每帧重画的窗口 8.7% CPU。手法不缺，缺的是**花钱的场景**。这一条只有用户
能答（他知道自己什么时候觉得卡/耗电/风扇响）。

为了让答案一到就能直接动手，先把四个分支的测量方案、改动候选、验收阈值写好。

## 分支表

| 用户答案 | 先量什么（10 分钟内可做） | 第一条改动 | 验收（ADR 0001 口径） |
|---|---|---|---|
| **视频播放** | 真机会话 + 一个 4K60 视频（mpv --hwdec）看 GPU busy / 帧时 / 掉帧 | 视频窗的私有底衬不抓（有 alpha 的播放器窗口目前会抓整块） | 帧时中位不退化，GPU busy 中位降 ≥10%，画面逐像素一致 |
| **全屏游戏 160Hz** | 真机才准；同会话切 force_render_hz=0 对比 | 直通路径优先：全屏窗不建金字塔、不复制离屏 | 掉帧数下降，拖拽延迟分位不退化 |
| **4K / 2 倍缩放** | headless 起 3840x2160@2x，量 趟/帧、装饰 ms/帧、GPU busy | 装饰直画（省每窗一趟 + 一次纹理采样） | 装饰那部分趟数降 ≥30%，截图逐像素差 0 |
| **多窗口（几十个）** | headless 起 30 窗（改 busy 场景窗数），量 趟/帧、CPU% | 被遮挡条目跳过合成 | CPU% 降 ≥10%，遮挡场景画面逐像素一致 |
| **其实没觉得慢** | 不需要 | 停；只核算已合入的 e7022a1 与 c1702b9 是否留 | 拿不到数字就撤 e7022a1 |

## 缺的两个前置许可（会再问一次）

1. `sudo sysctl kernel.perf_event_paranoid=1` —— 否则 CPU 侧没有火焰图，只能靠
   `VIDOW_RENDER_STATS` 那 1.8% 的覆盖面猜；
2. 换构建重启真机会话 —— 否则拿不到上屏节奏与 4K/高刷的真实数字（会掉所有窗口）。

## 不做什么

- 不为了「有优化提交」而做微优化：ADR 0002 已证明现有场景里没有可省的东西。
- 不写 `test-perf.sh` 阈值门禁（见 ADR 0001 的后果一节）。
